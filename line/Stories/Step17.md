### R1a-1 Keys, declarations and the four kinds

- **Outcome:** `Spellbound.Core.Observations` holds `ObservationKey` (the text `package.subject.name`, two or more lower-case segments of letters, digits and underscores joined by dots, with its FNV hash and its package, the first segment), `ObservationKind` (`Counter`, `Occurrence`, `Gauge`, `Cost`, the four the design closes), `ObservationUnit` (a readonly struct with a name and the named defaults `Count`, `Milliseconds`, `Bytes`, `Seconds`, `Ratio`; a consumer makes its own), `ObservationDeclaration` (key, kind, description, unit, default budget, default quality level) and the four declared types `Counter`, `Occurrence`, `Gauge` and `Cost`, each sealed, each holding its declaration and nothing mutable. `CoreKit.Observations.Counter(key, description)`, `Occurrence(key, description)`, `Gauge(key, description, unit)` and `Cost(key, description, unit, defaultBudget, defaultQualityLevel)` make them; the description is required and an empty one throws. `CoreKit.Observations.Reason(name)` registers a reason name once through Core's hash registry and returns its id, `ReasonName(id)` gives the word back. `CoreKit.Observations.Declared()` lists every declaration: the registry is append-only inside Core, reset on `SubsystemRegistration`, and a declared type registers itself again on first use after the reset, so a declaration in a static field survives a play mode entered with domain reload off; `Declared()` also runs the static constructors of every type in a Spellbound assembly that holds a public static field of one of the four types, so the list is complete with nothing running.
- **Rules:** a key declared twice with the same kind and description returns the first declaration; a second declaration of a key with another kind or description throws, so a duplicate shows at static initialisation and not in a report. No key, description or budget is a literal of Core's except the two clock keys and the log keys of R1a-4.
- **Done:** edit-mode tests on the key form (accepted and refused texts), the hash, the package, each kind, a custom unit, the required description, the duplicate rules, a reason round trip, `Declared()` after a reset and over an assembly whose static field was never touched.

### R1a-2 The per-world context

- **Outcome:** `ObservationContext` is one world's readings: `CoreKit.Observations.CreateContext(name)` and `CreateContext(name, settings)` make one, `ObservationContext.Discard` is the one immutable instance that records nothing and holds no state, and `Dispose()` removes a context from `ObservationContexts.All`, Core's list of live contexts. `Counter.Add(context)`, `Add(context, reasonId)` and `Add(context, amount)`, `Occurrence.Record(context, tick, subject)` and `Record(context, tick, subject, detail)`, `Gauge.Set(context, value)`, `Cost.Record(context, amount)` and `Cost.Measure(context)` (a disposable scope that records the elapsed milliseconds) report into it. `context.Read(package, readings)` fills a caller-owned list of `ObservationReading` (key, kind, value, count, peak, budget, quality level, unit, version) without allocating, `TryRead(key, out reading)` reads one, `ReadReasons(key, reasons)` lists a counter's counts by reason, `Version(key)` changes only when that key's value, budget or level changes, `PackageVersion(package)` when any key of the package does, `SetBudget(key, budget)` and `SetQualityLevel(key, level)` override the declaration's defaults, and `ObservationSettings` (a ScriptableObject of budget and quality level overrides by key, applied when the context is created) carries a project's values. `CoreKit.Observations.Compare(before, after, ratios)` gives the ratio per key of two reading lists.
- **Rules:** a context is read and written on the main thread; a job's queue is R1b's. A key with no reading is not listed by `Read`. Nothing in Core looks a context up: every door takes it as its last explicit argument (rule 9).
- **Done:** edit-mode tests on each kind's report and reading, the reason counts, the two versions, the budget and level overrides from `SetBudget`, `SetQualityLevel` and a settings asset, Discard recording nothing, two contexts never sharing a reading, the live list on create and dispose, `Compare`, and `Read_NoAllocation` over a pre-sized list.
