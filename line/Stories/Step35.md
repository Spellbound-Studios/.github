### R6a-1 `InventoryTransaction`, the accounts and the commit

- **Outcome:** `InventoryTransaction`, a pooled sealed class acquired by `InventoryTransaction.Begin(in IntentKey key)`, takes steps `Move(source, sourceSlot, destination, destinationSlot, quantity)`, `Swap(first, firstSlot, second, secondSlot)`, `Mint(destination, destinationSlot, itemId, quantity, reason)`, `Mint(destination, itemId, quantity, reason)` (partial stacks then free slots, whole or nothing), and `Burn(source, sourceSlot, quantity, reason)`; `Commit(InventoryAccounts accounts)` returns a `TransactionReceipt` and returns the instance to the pool. Commit refuses a `None` key (`inventory.refused.intent_key`), then calls `accounts.Intents.Check`: `Applied` answers the kept receipt without touching a container and counts `inventory.transactions.repeated`; `Stale` refuses (`inventory.refused.stale_intent`) and records nothing; `Unseen` validates every step over a scratch of the touched slots, asking the write gate once per distinct container (`inventory.refused.write_gate`), the slot range (`inventory.refused.slot`), the quantity against the source (`inventory.refused.quantity`), the destination provider's knowledge of the id (`inventory.refused.unknown_item`), the stack room (`inventory.refused.capacity`) and `CanAcceptItem` on every destination slot, stacking included (`inventory.refused.slot_kind`); a transaction with no steps is refused (`inventory.refused.no_steps`). On a refusal nothing is written. On success every touched slot is written once with its final value, each reason's mint and burn quantities are tallied per item id in the accounts, `inventory.transactions.applied` is counted and `accounts.Committed` is raised with the receipt. Both outcomes are recorded in the ledger, so a repeated key answers the same receipt. `InventoryAccounts` (one per world instance, `InventoryKit.CreateAccounts(IntentLedger intents, ObservationContext observations, IContainerWriteGate writeGate = null)`) holds the ledger, the context, the gate (`OpenWriteGate.Instance` by default), the registered containers (`Register`, `Unregister`) and the per-item mint and burn tallies (`MintedOf(itemId)`, `BurnedOf(itemId)`). `ItemDefinitionSet.TryGetItemInfo` reads a dictionary built once and rebuilt on `OnValidate` (finding 11).
- **Rules:** the block above; the engine gains `internal` members for the transaction's scratch and writes and no new public writer; the ledger is Core's, called as `Check` then `Record`; a refusal is a receipt, never an exception, except a `null` accounts argument or a step on a committed instance, which throw.
- **Regression contract:** every existing test passes; `TryAddItem`, `TryTakeItem`, `TryTransferItem` and `TrySetItemAt` behave as the seam left them.
- **Done:** tests for each refusal reason, for the two-slot move that writes both or neither, for the swap, for the auto-placed mint across a partial stack and a free slot, for the repeated key (same receipt, no second write), for the stale key and for the `None` key; `Surface.txt` regenerated.
