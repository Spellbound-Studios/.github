## The stories of step 15.4: Send, Get latest and Put back (A5a, with ArtPipeline#25, #26 and #29)

Step 15.4 gives the art registry its one button: the art window of the registry project gains a Send tab where an artist picks items and sends them as a reviewed branch without touching git, sees each waiting request's state and the reviewer's comment, receives everyone's merged work with Get latest and restores one item with Put back; the setup check and the git checks become rows of the same window; the texture, item folder and pivot lock checks join the registry's Model kind; Send writes each item's record and thumbnail; the rules, kinds, roles and records show as tables in the Inspector; and each artist's own application picks the hints. Thirteen stories: three Ready stories first (ArtPipeline#25, the item record, the role definition and the game's record as ArtPipeline assets; ArtPipeline#26, the picture that keeps a model's own materials; ArtPipeline#29, the declared dependencies and the sheet's fallbacks), then A5a-1 to A5a-10. The split is the plan's; the outcomes are the epic's. Facts are marked **verified** with the date or **verify before building on it**. Two repositories change, each on a branch of its own: ArtPipeline (`a5a-send` into `beta`, built in the worktree `_probes/ArtSend` cut from `origin/beta` 20ce2c3) and ArtRegistry (`a5a-registry` into `main`, built in the worktree `_probes/ArtRegistrySend` cut from `origin/main` 8b0765c), each with its own batch editor; Core is read at its `dev` head 70f6b4e and UI at its `beta` head ab1b53a and neither is edited. ArtPipeline merges first, because the registry installs it. Steps 18 (GeoForge, WorldForge) and 20 (Core, a Navigation spike) run at the same time in other sessions; nothing here edits their repositories.

Applies to every story of the step:

- **Rules:** the rules of steps 1 to 15.3 hold (spelled-out names, one type per file, explicit access modifiers, no comments or XML docs, the copyright line on every new C# file, logging through Core, the studio's Rider formatting; a value a game or a studio might tune is a serialized field with a default, never a literal in logic; a gap in Core or UI is raised and stops the story; the lead never touches git in a shared checkout; nothing merges to a branch a game follows without the developer's hand). No new dependency: git, Git LFS and gh are the machine's tools that setup installs; no JSON is parsed or written by anything this step adds (gh is asked for tab-separated fields with `--template` or `--jq -r`, and git for plain lines).
