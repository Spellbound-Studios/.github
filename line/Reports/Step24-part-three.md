## Why the seams carried so much

Each game compiles into one Assembly-CSharp, so a game's move is green only when every file is re-pointed, and Character's kept ragdoll script GUIDs and the frictionless material's GUID collide with the game's copies until Controller leaves. The seam therefore took, with the editor closed, the manifest, the deletions, the material under the kept GUID, the shared types the states build on and the tests, then opened once to resolve the lock and record the `error CS` file list, leaving a red tree whose remaining errors were exactly the builder's files. The sign-off read each seam and build diff together as one story's change.

## The developer's answers

`questions.md` asked three questions and `answers.env` took the recommendation on each: Corsairs' step lift values become a game-side `StepLiftSettings` with defaults 1.5 and 25 (answer 1); Corsairs builds its own camera rig and follow prefabs over Character.Cinemachine (answer 2); Saboteer's two ragdoll profile values `defaultBlendOutSeconds` and `defaultBlendHoldSeconds`, which no code reads, are let go, the YAML lines untouched (answer 3).
